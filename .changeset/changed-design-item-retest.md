When a story changes and the newly approved design gives an existing test a different expected result, the run now updates that test instead of running it unchanged. Before, such an item was reported as "already tested", the old test failed on the earlier expectation, the failure was treated as a moved locator, and nothing was corrected. Now the design tool's result and the approval note name the changed items with what they expected before and expect now; the run may rewrite the scenarios and tests of those items and no others; the suite's first automatic run waits a few turns for those edits; their failures are no longer sent to the locator healer; a rewritten scenario must have a test of its name; and a changed item whose scenario and test were both left untouched is pointed out to the agent once and then to the reviewer. This applies only when the story is known to have changed: a story last run before this release is designed once more and its tests are run as they are. Tests of unchanged items stay protected as before.

Also: with `--approval file`, the approval request file now carries `note`, the text the terminal prompt shows the reviewer (the cases and their state, what is already tested, what changed). And the rule that protects a passing test no longer mistakes the tag comments above the following test for a change to it, which had refused marking a failing test as a known bug.
